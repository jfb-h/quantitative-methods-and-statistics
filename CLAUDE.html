Style Guide for Quantitative Methods and Statistics Course

Author: Jakob Hoffmann, Economic Geography Group, LMU Munich Course: Masters in Human Geography - Quantitative Methods and Statistics Created: 2026-01-06

This document captures the style, conventions, and patterns used throughout the course materials for future reference and consistency.

1. Overall Course Philosophy & Structure

Course Approach

  • Applied focus: Emphasis on practical skills over theoretical proofs
  • Programming-first: Using R as the primary medium for learning statistics
  • Reproducible research: Heavy use of Quarto notebooks for literate programming
  • Build gradually: Starting from basics (data wrangling, visualization) before moving to inference and modeling
  • Real data: Using authentic datasets (Gapminder, Our World in Data) rather than toy examples
  • Modern statistics: Incorporating Bayesian inference alongside traditional approaches

Course Structure

The course follows a clear progression: 1. R Basics (Sessions 1-3): Data wrangling, visualization, descriptive statistics 2. Stochastic Models (Session 4): Probability & simulation 3. Statistical Inference (Session 5): Sampling, estimation & uncertainty 4. Linear Regression (Sessions 6-7): Basics, prediction, transformations 5. Advanced Regression (Session 8): Multiple regression, interactions, smooth effects 6. Causal Inference (Sessions 9-10): Experiments and observational studies 7. Advanced Topics (Sessions 11-13): GLMs, random effects, dependent data

Assessment

  • 60-minute exam testing both theoretical and practical skills
  • No prerequisites in statistics or programming assumed

2. Content Style & Pedagogical Approach

Writing Style

  • Conversational but precise: Friendly tone without sacrificing accuracy
  • Motivational openings: Start chapters with “why” questions
    • Example: “Why programming?” (Chapter 1)
    • Example: “Why build statistical models?” (Chapter 6)
  • Bridge theory and practice: Always connect concepts to real applications

Content Structure Pattern

Most chapters follow this structure: 1. Motivation: Why this topic matters 2. Conceptual introduction: Intuitive explanation before formalism 3. Code demonstration: Show it in action with real data 4. Exercises: Progressive difficulty, scaffolded learning 5. Practical considerations: Warnings, gotchas, best practices

Pedagogical Techniques

Show, Don’t Just Tell

  • Start with code examples, then explain
  • Use visualization heavily to build intuition
  • Simulation as a teaching tool (especially for probability/inference)

Progressive Complexity

  • Begin with simple cases (univariate, single parameter)
  • Build up gradually (multivariate, multiple parameters)
  • Revisit concepts at increasing depth

Emphasize Intuition

  • Prefer geometric/visual explanations over algebra when possible
  • Use analogies and plain language first
  • Mathematical notation comes after intuitive understanding

Best Practices Sections

  • Include explicit “Best practice:” callouts in the text
  • Example: Variable naming conventions
  • Example: When to use keyword vs positional arguments

Learning by Doing

  • Heavy use of exercises throughout (not just at the end)
  • Empty code chunks provided for students to fill in
  • Progressive exercises that build on each other

3. Language & Tone

Writing Voice

  • Second person when addressing students directly: “you should…”, “we can see…”
  • First person plural for shared exploration: “Let’s create…”, “We can compute…”
  • Imperative for instructions: “Run the code”, “Create a variable”

Technical Terminology

  • Introduce carefully: Define terms on first use
  • Use consistently: Stick to one term (e.g., “data frame” not “dataframe” or “DataFrame”)
  • Provide synonyms: Note alternative terms in parentheses
    • Example: “outcome or dependent variable”
    • Example: “predictors or independent variables”

Code References

  • Use backticks for inline code: ggplot2, tidyverse, read_csv()
  • Use backticks for R objects and functions: df$column, mean()
  • Use backticks for file paths: data/gapminder.csv

Mathematical Notation

  • Introduce notation gradually
  • Always explain symbols when first used
  • Use standard conventions:
    • Greek letters for parameters (α, β, θ, μ, σ)
    • Latin letters for data/variables (x, y, n)
    • Boldface for vectors/matrices (when needed)
    • Subscript i for individual observations (x_i, y_i)

Emphasis & Highlighting

  • Bold for key concepts and important terms
  • Italics for emphasis and Latin phrases
  • Code formatting for technical terms, functions, packages
  • “Quotes” for categorical values, labels, and string examples

4. Code Style & Conventions

R Code Style

Variable Naming

  • Lowercase with underscores: my_variable, sample_size, growth_rate
  • Descriptive names: Prefer clarity over brevity
  • Data frames: Often just df for temporary, or descriptive like gapminder, emissions
  • Avoid dots: Modern style uses underscores, not dots (my_var not my.var)
  • Temporary objects: Single letters ok in loops (i, x, y) or short contexts

Code Formatting

  • Spacing: Space around operators (x = 5, not x=5)

  • Line length: Break long function calls across multiple lines

  • Alignment: Align arguments vertically when breaking lines

    mutate(gapminder,
       total_gdp = gdpPercap * pop,
       gdp_billions = total_gdp / 1e9,
       gdp_trillions = gdp_billions / 1000)

  • Indentation: 4 spaces (or 2 for nested contexts)

Function Calls

  • Positional arguments: Use for first 1-2 obvious arguments

  • Named arguments: Use for all others, especially optional ones

  • Preferred pattern: function(data, main_arg, keyword = value)

    # Good
round(3.14159, digits = 2)

# Also acceptable
round(3.14159, 2)

# Avoid
round(digits = 2, x = 3.14159)

Pipe Operator

  • Use |> (native pipe) throughout the course

  • One operation per line in pipelines for readability

  • Indent continuation lines

    gapminder |>
  filter(continent == "Europe") |>
  select(country, year, gdpPercap) |>
  pivot_wider(names_from = year, values_from = gdpPercap)

Comments

  • Use sparingly: Let code be self-documenting where possible
  • Explain why, not what: Comment on reasoning, not obvious operations
  • Section headers: Use # Section name for major sections
  • Inline comments: After code, with two spaces: x <- 5 # initialize counter

Code Chunk Options

  • Default: Show both code and output
  • eval = FALSE: Show code without running (for demonstration)
  • warning = FALSE, message = FALSE: Suppress package loading messages
  • fig.width, fig.height: Specify plot dimensions in inches
  • No chunk labels used (Quarto handles this automatically)

Package Loading

  • Load all packages at the start of the document
  • Use library(tidyverse) for the full suite
  • Namespace notation for single functions: arrow::read_parquet()
  • Comment out install.packages() after first use

5. Document Structure Patterns

YAML Header

Standard format for all chapters:

---
title: "Quantitative Methods and Statistics"
subtitle: "An applied course using the `R` programming language"
author:
  - name: "Jakob Hoffmann"
    affiliation: "Economic Geography Group, LMU Munich"
format:
  html:
    toc: true
---

Heading Hierarchy

  • # for major sections (e.g., “Loading data”, “Statistical inference”)
  • ## for subsections (e.g., “CSV files”, “The arithmetic mean”)
  • ### for sub-subsections (e.g., “Exercises”, “Weighted mean”)
  • Rarely go deeper than ###

Section Patterns

Data Loading Section

  • Explain data source and relevance
  • Show data structure with glimpse() or similar
  • Note any data preparation steps
  • Provide data dictionary for key variables

Concept Introduction Section

  • Start with intuitive explanation
  • Show mathematical notation
  • Demonstrate with code
  • Visualize results
  • Discuss interpretation

Exercise Section

  • Number exercises clearly (1, 2, 3…)
  • Provide empty code chunks for solutions
  • Build progressively in difficulty
  • Some exercises refer back to previous work

Cross-References

  • Reference other chapters: “As we saw before”, “We will come back to this”
  • Reference specific locations: “Look at the global environment in RStudio”
  • Reference external resources with hyperlinks: book on data visualisation

6. Exercise Design Patterns

Exercise Types

Skill-Building Exercises

  • Practice a single new technique
  • Located immediately after introducing the technique
  • Example: “Create a variable called my_age”

Integration Exercises

  • Combine multiple techniques
  • Located at section or chapter end
  • Example: “Create a pipeline that calculates total GDP, groups by continent…”

Open-Ended Exercises

  • Require creative problem-solving
  • Example: “Investigate the hypothesis that economic development in Europe has been more convergent…”

Exercise Scaffolding

  • Minimal guidance: For reinforcement of just-taught skills
  • Hints in prompt: Point to specific functions or approaches
  • Code starters: Provide partial code to complete
  • Multi-step: Break complex tasks into numbered steps

Exercise Placement

  • Inline exercises: After introducing a new function or concept
  • Section exercises: Combine techniques from the section
  • Chapter exercises: Integrate all chapter content

7. Mathematical Notation Conventions

General Principles

  • LaTeX in $$ or $: Use display math ($$...$$) for key equations, inline ($...$) for references
  • Define all symbols: Never use a symbol without defining it
  • Standard notation: Follow statistical conventions

Common Notation

  • Variables:
    • Scalars: lowercase italic (x, y, n, i)
    • Vectors: lowercase bold or with index (x_i for individual elements)
    • Matrices: uppercase bold (rare in this course)
  • Parameters: Greek letters
    • μ (mu): mean/location
    • σ (sigma): standard deviation
    • α (alpha): intercept
    • β (beta): slope/coefficient
    • θ (theta): general parameter
    • λ (lambda): rate parameter
  • Distributions:
    • Roman/text font: Normal, Bernoulli, Binomial, Beta, etc.
    • Notation: y ~ Normal(μ, σ) (using tilde for “distributed as”)
  • Functions:
    • Text font: log, exp, mean, etc.
    • \textrm{...} in LaTeX for multi-letter text

Equation Formatting

# Display equations (centered, numbered implicitly)
$$
y \sim \textrm{Normal}(\mu, \sigma)
$$

# With alignment (for multi-line)
$$
\begin{align}
y &\sim \textrm{Normal}(\mu, \sigma) \\
\mu &= \alpha + x\beta
\end{align}
$$

# Summation notation
$$
\bar{x} = \frac{1}{n} \sum_{i=1}^n x_i
$$

# Products
$$
\prod_{i=1}^n x_i
$$

# Conditional probability
$$
p(\theta | y)
$$

Mathematical Writing Style

  • Mix prose and equations naturally
  • Read equations aloud to check flow
  • Example: “The mean is defined as \(\bar{x} = \frac{1}{n} \sum_{i=1}^n x_i\), where \(n\) is the sample size.”

8. Visualization Patterns

ggplot2 Style

Basic Structure

ggplot(
  data = dataset,
  mapping = aes(x = var1, y = var2, color = var3)
) +
  geom_point() +
  scale_x_log10() +
  scale_color_brewer(palette = "Set1") +
  labs(
    x = "X axis label",
    y = "Y axis label",
    color = "Legend title",
    title = "Main title",
    subtitle = "Descriptive subtitle with context",
    caption = "Source: Data source"
  ) +
  theme_minimal() +
  theme(legend.position = "bottom")

Aesthetic Choices

  • Colors: Use scale_color_brewer() with named palettes (“Set1”, “Dark2”, etc.)
  • Point colors: “tomato” is the go-to color for single-color plots
  • Themes: Prefer theme_minimal() for clean, modern look
  • Legend position: Often "bottom" to maximize plot area

Progressive Plot Building

  • Build plots incrementally in teaching contexts:

    p <- ggplot(data, aes(x, y))
p <- p + geom_point()
p <- p + scale_x_log10()
p

  • Show final version with all code together for reference

Common Geometries

  • Points: geom_point() for scatter plots
  • Lines: geom_line() for time series
  • Bars: geom_bar() or geom_col() for categorical
  • Histograms: geom_histogram() with color = "white" for bin borders
  • Density: geom_density() as smooth alternative to histogram
  • Reference lines: geom_vline(), geom_hline(), geom_abline()

Faceting

  • Use facet_wrap() for small multiples
  • Consider scales = "free_y" when ranges differ greatly
  • Example: facet_wrap(~continent, scales = "free_y", nrow = 1)

Saving Plots

ggsave("filename.png", plot_object, width = 8, height = 8, dpi = 320)
  • Width/height in inches (default)
  • High DPI (300-320) for publication quality
  • PNG format for raster graphics

9. Data Wrangling Patterns

Tidyverse Workflow

Common Operations

  1. Select columns: select(df, col1, col2) or select(df, -col_to_drop)
  2. Filter rows: filter(df, condition1, condition2)
  3. Create/modify columns: mutate(df, new_col = expression)
  4. Group operations: group_by(df, group_var) |> summarize(stat = function(var))
  5. Arrange rows: arrange(df, var) or arrange(df, desc(var))

Pipeline Pattern

Prefer pipelines over nested functions:

# Good: Pipeline
result <- data |>
  filter(year == 2020) |>
  select(country, gdp) |>
  arrange(desc(gdp))

# Avoid: Nested functions
result <- arrange(select(filter(data, year == 2020), country, gdp), desc(gdp))

Data Transformation Patterns

Categorical variables:

mutate(df,
  category = case_when(
    var < threshold1 ~ "Low",
    var < threshold2 ~ "Medium",
    var >= threshold2 ~ "High",
    TRUE ~ NA
  ),
  category = factor(category, levels = c("Low", "Medium", "High"), ordered = TRUE)
)

Conditional downloads:

if (!file.exists("data/filename.parquet")) {
  df <- read_csv("url")
  arrow::write_parquet(df, "data/filename.parquet")
}

Group summaries:

df |>
  summarize(
    count = n(),
    mean_value = mean(variable),
    sd_value = sd(variable),
    .by = grouping_var
  )

10. Dataset Conventions

Primary Teaching Datasets

  1. Gapminder: Life expectancy, GDP, population by country (1952-2007)
    • File: data/gapminder.csv
    • Used for: Basic R, wrangling, visualization
  2. Our World in Data: CO₂ emissions, population, GDP
    • Files: data/emissions-raw.parquet, data/population-raw.parquet, etc.
    • Used for: Descriptive statistics, data joins

Data Loading Pattern

# Option 1: Direct read
df <- read_csv("data/filename.csv")

# Option 2: With caching
if (!file.exists("data/cached.parquet")) {
  df <- read_csv("url_or_source")
  arrow::write_parquet(df, "data/cached.parquet")
}
df <- arrow::read_parquet("data/cached.parquet")

# Option 3: From package
library(gapminder)
data(gapminder)

Data Preparation Pattern

  1. Load raw data
  2. Show structure: glimpse(df) or print first few rows
  3. Select/rename columns for clarity
  4. Filter to relevant subset
  5. Create derived variables if needed
  6. Handle missing values explicitly
  7. Save cleaned version if appropriate

11. Simulation & Probability Patterns

Simulation Workflow

  1. Set parameters: Define model parameters explicitly
  2. Specify model: Write out the distribution/model
  3. Simulate data: Use rnorm(), rbinom(), etc.
  4. Visualize: Plot simulated data
  5. Compare: Overlay true distribution with stat_function()

Example Pattern

# 1. Parameters
mu <- 166
sigma <- 7
n <- 100

# 2. Model
# height ~ Normal(mu=166, sigma=7)

# 3. Simulate
simulations <- rnorm(n = n, mean = mu, sd = sigma)

# 4. Visualize
ggplot(data.frame(simulations), aes(x = simulations)) +
  geom_histogram(aes(y = after_stat(density)), bins = 20, fill = "tomato") +
  stat_function(fun = dnorm, args = list(mean = mu, sd = sigma))

Reproducibility

  • Use set.seed() for reproducible random number generation
  • Example: set.seed(123)

12. Common Warnings & Caveats

Pedagogical Warnings

  • Note when something is a simplification: “This is just a model…”
  • Warn about common pitfalls: “A common beginner mistake is…”
  • Note computational limitations: “For most real analyses, we need…”

Statistical Warnings

  • Outliers: “The mean is sensitive to outliers”
  • Missing data: “Simply dropping rows with missing values can be dangerous”
  • Log scales: “Some getting used to is required… have a tendency to confuse people”
  • Sampling: “Random sampling ensures representative sample, but also produces uncertainty”

Code Warnings

  • LLMs: Warn about uncritical use of ChatGPT/Copilot
  • Package installation: “Remove or comment out the install statement after first use”
  • Overwriting variables: “Be careful, overwriting variables can lead to unexpected behavior”

15. Special Teaching Techniques

Simulation as Pedagogy

  • Use simulation extensively to build intuition about:
    • Probability distributions
    • Sampling variation
    • Uncertainty quantification
    • Data generating processes

Incremental Complexity

  • Start with univariate, move to multivariate
  • Start with single parameter, add parameters gradually
  • Start with visualization, then add formal analysis

Bridge Multiple Paradigms

  • Show both tidyverse and base R where relevant
  • Mention frequentist concepts while teaching Bayesian
  • Connect to both theory and practice

Active Learning

  • Frequent exercises embedded in content
  • Empty code chunks for hands-on practice
  • Encourage experimentation: “Play around with different values…”

16. Writing Checklist

When creating new content, ensure:

Summary of Key Style Elements

  1. Progressive pedagogy: Simple to complex, concrete to abstract
  2. Code-first teaching: Show in action before explaining theory
  3. Heavy visualization: Every concept illustrated graphically
  4. Simulation emphasis: Use simulation to build intuition
  5. Real datasets: Authentic, interesting data throughout
  6. Tidyverse focus: Modern R workflow with pipes and tidy principles
  7. Bayesian perspective: Probability for inference, though not dogmatic
  8. Practical orientation: Applied statistics for social science research
  9. Reproducible workflow: Quarto notebooks throughout
  10. Active learning: Frequent, progressive exercises

This style guide should be consulted when creating new content or revising existing materials to maintain consistency throughout the course.
